# Repository guidance

- This repository has two independent package boundaries and lockfiles: the root package is the Arco CLI/template publisher; `arco-design-pro-vite/` is the Vue application template. Run dependency commands in the directory whose `package.json` you are changing; never regenerate one lockfile from the other directory.
- The application’s authoritative verification command is `cd arco-design-pro-vite && pnpm check`, which runs type-check, Oxlint, and production build in that order. Focused commands are `pnpm type:check`, `pnpm lint`, and `pnpm build`.
- CI runs from `arco-design-pro-vite/` with Node `20.19.0`, pnpm 11, `pnpm install --frozen-lockfile --ignore-scripts`, then `pnpm check`. Keep the application lockfile compatible with pnpm 9+; do not add an exact pnpm patch-version requirement.
- The root package uses the root `pnpm-lock.yaml` and Husky commit-msg validation (`pnpm commitlint --edit <message-file>`). Root dependency changes require updating the root lockfile separately.
- The production UI dependency is the fork `@ekworp/arco-design-vue`; do not reintroduce `@arco-design/web-vue` imports.
- Arco components and icons are auto-imported by `config/plugin/arcoResolver.ts`, which wraps the resolver to rewrite official package paths to `@ekworp/arco-design-vue`. Do not restore `app.use(ArcoVue)` or `app.use(ArcoVueIcon)` in `src/main.ts`.
- `components.d.ts` is generated by `unplugin-vue-components`; update it through a build rather than hand-maintaining its component list.
- Mock data is loaded only when `import.meta.env.DEV` is true in `src/main.ts`; keep `mockjs` out of production code paths.
- ECharts modules are registered centrally in `src/components/index.ts`; use `echarts/core` or type-only imports, not the runtime `echarts` root entry, in feature components.
- Vite config files are ESM (`.ts` imports include extensions and use `import.meta.dirname`); CommonJS tool configs must use `.cjs` because the app package has `"type": "module"`.
- The custom chart wrapper accepts the singular `option` prop, matching all `<Chart :option="...">` call sites.
- Use the configured pnpm registry for installs/outdated checks when available; do not silently switch lockfile generation to another registry or package manager.
