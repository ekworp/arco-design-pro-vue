# Repository guidance

- This repository has two independent package boundaries and lockfiles: the root package (`@ekworp/arco-design-pro-vue`) publishes the template generator, while `arco-design-pro-vite/` is the private Vue application template. Run dependency commands in the directory whose `package.json` you are changing; never regenerate one lockfile from the other directory.
- The root package exposes `bin/cli.cjs`; its supported published CLI templates are `vite` and `vite-simple`. Test the CLI with `node bin/cli.cjs --help` or `node bin/cli.cjs init <directory> --no-install --no-git`; verify package contents with `pnpm pack --dry-run`.
- The root generator invokes `scripts/vite.js`, which copies the app template and removes non-selected package-manager lockfiles. Keep its `.cjs` config mappings and its async Prettier 3 formatting compatible when changing template files.
- The application’s authoritative verification command is `cd arco-design-pro-vite && pnpm check`, which runs type-check, Oxlint, and production build in that order. Focused commands are `pnpm type:check`, `pnpm lint`, and `pnpm build` from that directory.
- Application CI and the npm publish workflow use Node 24 and pnpm 11; application CI runs `pnpm install --frozen-lockfile --ignore-scripts`, then `pnpm check`, while tagged publish runs the same application check before publishing the root package and creating a GitHub Release.
- The root package uses the root `pnpm-lock.yaml`; root dependency changes require updating that lockfile. The app uses `arco-design-pro-vite/pnpm-lock.yaml`, with its local overrides and build permissions preserved.
- Production UI imports must use the fork `@ekworp/arco-design-vue`; do not reintroduce `@arco-design/web-vue` imports. Arco components are auto-imported by `config/plugin/arcoResolver.ts`; do not restore global `ArcoVue` or `ArcoVueIcon` registration.
- `components.d.ts` is generated by `unplugin-vue-components`; update it through an application build rather than hand-maintaining its component list.
- Route metadata must keep using string icons such as `icon: 'icon-dashboard'`. `config/plugin/arcoIconEntry.ts` scans route files and generates the virtual, shared `icons` chunk; do not replace this with manual route imports or runtime `compile()`.
- Mock data is loaded only when `import.meta.env.DEV` is true in `src/main.ts`; keep `mockjs` out of production code paths.
- ECharts modules are registered in `src/components/chart/index.vue`; chart pages must import `Chart` locally so ECharts stays out of the initial preload. Use `echarts/core` or type-only imports, not the runtime `echarts` root entry, in feature components.
- The custom chart wrapper accepts the singular `option` prop, matching all `<Chart :option="...">` call sites.
- Locale messages and Arco component locales are dynamically loaded from `src/locale/index.ts`; preserve browser-language detection, saved user locale selection, and the separate language chunks.
- Vite config files are ESM (`.ts` imports include extensions and use `import.meta.dirname`); CommonJS tool configs must use `.cjs` because the app package has `"type": "module"`.
- Use the configured pnpm registry for installs/outdated checks when available; do not silently switch lockfile generation to another registry or package manager.
